알리바바가 **11월 16일** Qwen 계열 최상위 모델 **Qwen4-Max**를 내놨습니다. 기사 제목마다 같은 숫자 두 개가 나옵니다. **작업당 평균 비용 $4.43 → $1.67(약 62% 절감)**, 그리고 **자동차 부품 가공 프로그래밍 475분 → 24분(95% 단축)**.

숫자만 보면 "AI 쓰는 비용이 3분의 1로 줄고 일이 20배 빨라진다"로 읽힙니다. 그런데 구매·자재 일을 하면서 견적서 숫자를 매일 뜯어보는 입장에서 보면, **이 숫자가 어디서 어떻게 나왔는지**부터 확인하고 싶어집니다. 발표문과 해외 보도를 교차해서 정리했습니다.

## TL;DR

- **무엇**: 총 2.4조(2.4T) 파라미터 MoE, 토큰당 활성 710억(71B). 컨텍스트 100만 토큰, 텍스트·이미지·영상 입력.
- **가격**: 입력 100만 토큰당 $1.50, 출력 $4.50 (이전 세대 $2 / $6). 캐시 적중 입력은 $0.075.
- **$4.43→$1.67**: 알리바바 **자체 벤치마크(Work360)** 결과. 토큰 사용량 감소 + 단가 인하가 합쳐진 값.
- **475분→24분**: 협력사 **시연 사례 1건**. 감사받은 공장 실적이 아님.
- **가중치 비공개**: Max는 API 전용. 오픈웨이트는 "작은 모델부터 곧"이라는 예고만 있음.
- **실무 결론**: 토큰 단가보다 **"합격한 결과물 1건당 비용"**으로 직접 재봐야 함.

## 한눈에 보는 스펙

| 항목 | Qwen4-Max | 이전 세대 Qwen3.8-Max |
|---|---|---|
| 총 파라미터 | 2.4T (MoE) | 2.4T (MoE) |
| 토큰당 활성 파라미터 | 71B | 약 95B (71B가 25% 적다는 발표 기준 역산, 추정) |
| 컨텍스트 | 100만 토큰 | — |
| 입력 단가 (100만 토큰) | $1.50 | $2.00 |
| 출력 단가 (100만 토큰) | $4.50 | $6.00 |
| Work360 점수 | 52.69 | 47.74 |
| Work360 작업당 평균 비용 | **$1.67** | **$4.43** |
| 공개 형태 | API·QwenCloud 전용 (가중치 비공개) | — |

비교 삼아 보면, 해외 보도에 인용된 Claude Opus 5.5 출력 단가는 100만 토큰당 $20입니다. 단가만 놓고 보면 Qwen4-Max가 4배 넘게 쌉니다.

## $4.43 → $1.67, 무엇을 잰 숫자인가

**Work360**은 알리바바가 직접 만든 벤치마크입니다. 26개 대분야, 721개 세부 직무의 "어려운 실무 과제"를 모델에게 시키고 점수와 비용을 잽니다.

62% 절감은 두 가지가 곱해진 결과입니다.

1. **토큰을 덜 씀** — 같은 과제를 푸는 데 High 추론 모드에서 35%, 최고(Xhigh) 모드에서 24% 적은 토큰을 썼다고 합니다. 별도 시험(Terminal-Bench 4.0)에서는 48~49%까지 줄었습니다.
2. **단가 자체를 내림** — 입력 $2→$1.50, 출력 $6→$4.50(각 25% 인하).

토큰 0.65배 × 단가 0.75배 ≈ 0.49배인데 실제 발표치는 0.38배(62% 절감)라, 과제 구성이나 입출력 비율에 따라 차이가 더 벌어진 것으로 보입니다(추정).

여기서 짚을 점이 세 가지 있습니다.

- **출제자와 채점자가 같습니다.** Work360은 공개 리더보드가 없고, 발표에서 비교한 것도 자기 이전 모델뿐입니다. "다른 회사 모델보다 싸다"는 증거가 아니라 **"우리 이전 모델보다 싸졌다"**는 증거입니다.
- **외부 측정치는 다릅니다.** 독립 평가기관 Artificial Analysis 기준 작업당 비용은 **$3.27**로 나왔습니다(경쟁 모델 Kimi K3.1 Pro $3.68보다 약 11% 저렴). 시험 세트가 달라 $1.67과 직접 비교하면 안 되지만, "어디서 재도 $1.67"은 아니라는 뜻입니다.
- **재시도·검수 비용이 빠져 있습니다.** InfoWorld가 인용한 한 애널리스트는 "알리바바는 자기 도로에서 낸 연비를 공개한 것이고, 구매자의 청구서는 구매자가 달리는 도로에 달려 있다"고 했습니다. 실제 업무 비용에는 틀린 답 다시 돌리기, 사람이 확인하는 시간이 들어갑니다.

## 475분 → 24분, 무엇을 줄인 숫자인가

이 숫자는 **자동차 제조 협력사 시연**에서 나왔습니다. 가공물 하나의 **수작업 공작 프로그래밍**(CNC 가공 경로를 짜는 일) 시간을 약 475분에서 24분으로 줄였다는 내용입니다. 계산하면 24÷475 ≈ 5%, 즉 95% 단축이 맞습니다.

어떻게 줄였는지가 흥미롭습니다. 모델이 경로를 짠 뒤 **"과절삭(너무 깎임)"과 "덜 깎임"을 가공 전에 스스로 잡아내는 피드백 반복**을 돌렸다고 합니다. 사람이 시뮬레이션 돌려 보고 고치는 왕복을 모델이 대신한 셈입니다.

다만 이것도 **가공물 1건 시연**입니다. 공장 전체 라인 평균이나 외부 감사 결과가 아닙니다. 발표문에는 이 밖에도 다음 사례가 있습니다.

| 사례 | 발표 내용 | 성격 |
|---|---|---|
| 공작 프로그래밍 | 475분 → 24분 | 협력사 시연 1건 |
| 클라우드 스케줄링 | 오프라인 CPU 재배치 14배 이상 빨라짐 | 알리바바 자체 인프라 |
| 데이터 라벨링 호출 비용 | 평균 9~10% 절감 | 자체 벤치마크 |
| 금융 분석 | MCP 도구 90개로 시장 데이터 수집 → 엑셀·PPT 생성, 숫자마다 출처 추적 | 시연 |
| 소재 연구 | 48시간 무인 에이전트 실행으로 냉각제 분자 도출, 실험 검증 | 시연 |

## 구매·사무 실무자 관점에서 본 세 가지

저는 제조업 구매·자재 일을 하면서 업무 일부를 AI 에이전트에 맡겨 쓰고 있습니다. 그 입장에서 이번 발표에서 눈여겨본 점은 이렇습니다.

### 1. "토큰 단가"가 아니라 "합격한 결과 1건당 비용"으로 재야 한다

견적 비교할 때 단가만 보지 않고 불량률·납기·검수 공수까지 보는 것과 같습니다. AI도 마찬가지입니다. 예를 들어 "협력사 납기 회신 메일 50통을 읽고 입고 예정표를 갱신한다"는 일을 맡긴다면, 재야 할 것은:

- 50통 처리에 든 **실제 API 청구액**
- 틀려서 **다시 돌린 횟수**
- 사람이 **검수하는 데 쓴 시간**

이 세 개를 합친 값이 진짜 비용입니다. 해외 보도에서도 "토큰 100만 개 비용이 아니라 실제 업무 1,000건을 성공시키는 비용을 재라"는 조언이 나왔습니다.

### 2. 475분→24분은 "숙련자의 반복 확인 작업"에서 나왔다

이 사례가 줄인 것은 창의적 설계가 아니라 **"짜고 → 시뮬레이션 → 고치고"를 반복하는 확인 루프**입니다. 사무실로 옮기면 이런 일들이 같은 구조입니다.

- 발주서 수량·단가를 BOM·계약 단가표와 대조해 틀린 줄 찾기
- 대체 부품 후보를 데이터시트 사양과 하나씩 비교하기
- 단종(EOL) 공지 메일을 읽고 해당 품번의 재고·소요량 확인하기

정답을 기계적으로 검증할 수 있는 일일수록 효과가 큽니다. 반대로 협상처럼 정답이 없는 일은 시간 단축 폭이 작을 겁니다.

### 3. 가중치 비공개 = 사내 데이터는 밖으로 나간다

Qwen4-Max는 **API로만** 씁니다. 내려받아 사내 서버에서 돌릴 수 없습니다. 단가·거래처·도면 같은 민감 정보를 넣으려면 회사 보안 정책부터 확인해야 합니다. 알리바바는 Qwen4 계열의 **작은 오픈웨이트 모델**을 곧 내겠다고만 했습니다. 사내에 직접 설치해 쓰고 싶은 쪽이라면 그 공개를 기다리는 편이 현실적입니다.

## 써본다면 이렇게 시작하겠습니다

1. **평소 하는 반복 업무 1개**를 고릅니다(예: 주간 입고 예정 정리).
2. 실제 과거 데이터에서 **민감 정보를 지운 샘플 20건**을 만듭니다.
3. 지금 쓰는 도구(또는 사람)와 Qwen4-Max에 같은 과제를 주고 **정답률·소요 시간·청구액**을 기록합니다.
4. 정답률이 비슷하다면 그때 단가 차이가 의미를 가집니다.

발표 숫자는 "가능성이 있다"는 신호로만 받고, 결정은 내 업무 20건으로 한 시험 결과로 하는 게 맞다고 봅니다.
